# GIQ-109 — Basic unit tests for StyreIQ

Linear: [GIQ-109](https://linear.app/meltstudio/issue/GIQ-109)

## Context

The repo has no test runner (`AGENTS.md`: "no `test` script"). Three incidents were reported recently; the ticket doesn't name them. Open question: which ones? Until told, prioritise areas touched by the latest fixes: tenant/role isolation (GIQ-85), escalated tasks (GIQ-95), backup unit admin clearing, policy editor links (GIQ-91), welcome/task email ordering (GIQ-83), demo request (GIQ-90).

## Approach

1. **Runner**: add Vitest (+ `@vitest/coverage-v8`), `vitest.config.ts` with the `@/` alias, `node` environment (pure logic only; no Payload/DB). Scripts: `test`, `test:coverage`.
2. **CI**: add a `yarn test:coverage` step to `.github/workflows/_code_checks.yaml` (needs your OK, AGENTS.md says CI files require an explicit request, and the ticket AC asks for CI). Coverage summary printed in the job log.
3. **Tests** in `__tests__/` mirroring source (AGENTS.md convention), using realistic data (e.g. "Dirección de Comunicaciones" units, "Instagram" accounts, real-looking emails), no mocks of code under test:
   - `shared/utils`: role-hierarchy, rbac, organization-filter, hasSameValues, searchParams, safeUrl
   - `features/units/utils`: calcPathAndDepth, createUnitTree, filterTree, treePaginationAndFilter, ensureStyreIQUnit; `constants/adminAssignment`
   - `features/users/utils`: assignableRoles, permissionChangeEmail
   - `features/social-medias/utils`: assignable-user-options, post-storage
   - `features/compliance-tasks`: utils (date maths with fake timers), taskHelpers
   - `features/flags/utils`, `auth/utils/logoutReason`
   - Zod schemas: requestDemoSchema, auth, units, flags, policies
4. Final: run coverage, record % in the plan and report to PM.

## Out of scope

Payload endpoints/hooks needing DB, React component tests (could follow up with Testing Library + jsdom), E2E.

### Suspected bugs found while testing (source not changed)

- **Security/authz:** `patchSocialMedia` has only a tenant check (no role check, no admin validation; forces status to `pending_approval`); `scrapLatestPost` / `getSavedLatestPost` have no auth; `SocialMediaPosts` read/create/update open to everyone; welcome email HTML is not escaped (`welcomeEmailBody.ts`); `getServerTenantContext(null)` returns `null as unknown as User`.
- **Wrong results:** `updateUnit` returns `JSON.stringify(createUnit)` (the endpoint object); unit update form offers `pending` but API expects `pending_review`; root unit depth is 1 in endpoints vs 0 elsewhere; flag `assignedTo` users never fetched in dashboard; `findUsersWithIssues` filters on `role` not `roles`; `detectRisks` job reports success when tenants fail; `markAsResolved` 500 instead of 403; `setUserApprovalStatus` 401 instead of 403; role-request SDK reads `error.message` but endpoints return `{ error }`; rejected role requests have no audit entry; approve endpoint has no error handling; malformed `approved` treated as rejection; `NaN` unitId on non-numeric organization.
- **Reliability:** `scrapLatestPost` doesn't await storage; audit-log hooks write inside `setTimeout` (can be lost on serverless); `useRollCallStatus` loops if given a new array each render; user table cells remount each render (details dialog can close itself); logout uses `NEXT_PUBLIC_APP_URL` vs `NEXT_PUBLIC_BASE_URL` elsewhere.
- **Smaller:** compliance task update access compares `assignedUser`/`tenant` to ids (fails if populated); pre-due reminder stores days-until-due in `daysSinceDue`; roll-call frequency lookup can yield `NaN`; flag date filters shift a day west of UTC; checkbox-list mode throws outside `FormItem`; form-helper error summary is dead code; array child fields without `type` throw on Add; social_media_manager USERS permission vs access message mismatch; optional select hides "Clear selection" after change; `passwordUpdatedAt` invalid string fails as "Required"; dead `!user` check in dashboard layout.

### Additional suspected bugs from the hook tests (source not changed)

- `typeof x === 'object' ? x.id : x` throws when `tenant` is `null`: users `afterChange` (logged and swallowed) and policies `afterChange` (inside `setTimeout`, so an unhandled rejection; reachable when a super admin creates a policy with no tenant selected).
- `AuditLogAfterChange` throws and silently loses the entry when `social-medias`/`flags`/`organization_access` relations are unpopulated ids; `AuditLogAfterDelete` never links organizations for flags/accounts, so unit admins cannot see those delete entries.
- `injectTenantHook` on update returns `data?.tenant || value`: a non-super-admin may set the tenant through the data; a super admin gets null if none is sent.
- Policies `beforeValidate` resets every user's policy agreement before the policy is validated, so a failed create still resets them.
- `RoleRequests.beforeChange` only checks duplicate roles on create, so changing `requestedRole` on update bypasses it.
- Social-media `afterChange`: primary admin id has no falsy guard; turning off `isSharedCredential` doesn't cancel open tasks; users without a tenant are skipped with no audit entry; explicit `isSharedCredential: false` for TikTok/Twitter on create is overridden; shared-platform list contains an invalid `'x'`.
