# GIQ-109 — Basic unit tests for StyreIQ

Linear: [GIQ-109](https://linear.app/meltstudio/issue/GIQ-109)

## Context

The repo has no test runner (`AGENTS.md`: "no `test` script"). Three incidents were reported recently; the ticket doesn't name them. Open question: which ones? Until told, prioritise areas touched by the latest fixes: tenant/role isolation (GIQ-85), escalated tasks (GIQ-95), backup unit admin clearing, policy editor links (GIQ-91), welcome/task email ordering (GIQ-83), demo request (GIQ-90).

## Approach

1. **Runner**: add Vitest (+ `@vitest/coverage-v8`), `vitest.config.ts` with the `@/` alias, `node` environment (pure logic only; no Payload/DB). Scripts: `test`, `test:coverage`.
2. **CI**: add a `yarn test:coverage` step to `.github/workflows/_code_checks.yaml` (needs your OK, AGENTS.md says CI files require an explicit request, and the ticket AC asks for CI). Coverage summary printed in the job log.
3. **Tests** in `__tests__/` mirroring source (AGENTS.md convention), using realistic data (e.g. "Dirección de Comunicaciones" units, "Instagram" accounts, real-looking emails), no mocks of code under test:
   - `shared/utils`: role-hierarchy, rbac, organization-filter, hasSameValues, searchParams, safeUrl
   - `features/units/utils`: calcPathAndDepth, createUnitTree, filterTree, treePaginationAndFilter, ensureStyreIQUnit; `constants/adminAssignment`
   - `features/users/utils`: assignableRoles, permissionChangeEmail
   - `features/social-medias/utils`: assignable-user-options, post-storage
   - `features/compliance-tasks`: utils (date maths with fake timers), taskHelpers
   - `features/flags/utils`, `auth/utils/logoutReason`
   - Zod schemas: requestDemoSchema, auth, units, flags, policies
4. Final: run coverage, record % in the plan and report to PM.

## Out of scope

Payload endpoints/hooks needing DB, React component tests (could follow up with Testing Library + jsdom), E2E.

## Validation

- `yarn test` and `yarn test:coverage` pass locally; `yarn ci:checks`, `yarn ls-lint`, `yarn syncpack list-mismatches` pass
- Verify a deliberately broken rule (e.g. role hierarchy) fails a test
- Coverage % recorded here

## Risks

- Files that import Payload/env at module load may need `src/config/env.ts` stubs; skip those rather than mock heavily.
- New devDependencies need syncpack/yarn.lock updates.

## Results (2026-10-16)

- 13 test files, 96 tests, all passing (`yarn test`); `yarn ci:checks`, `yarn ls-lint`, `yarn syncpack list-mismatches` pass.
- Mutation check: changing the `unit_admin` rank in `role-hierarchy.ts` made 4 tests fail; reverted.
- Coverage (`yarn test:coverage`, all of `src/` excluding tests, types, migrations): **8.01% statements/lines, 69.43% branches, 28.55% functions**. Low overall because React components, Payload endpoints/hooks and pages (the bulk of `src/`) are not unit-tested; the covered files are the pure-logic modules listed above.
- Not covered (needs DB/Payload or a DOM): `organization-filter` (GIQ-85 isolation queries), `validateTenantAccess`, email sending flow ordering (GIQ-83), React components. Suggested follow-up: Testing Library + jsdom and Payload test doubles.
