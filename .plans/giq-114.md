# GIQ-114 — Welcome email shows another tenant's Additional resources

## Context

A user added to City of Raleigh received a welcome email with Randolph Macon's "Additional resources". Reproduced on ct-dev (2026-11-04): tenant A has a welcome email, tenant B has none; the create-user endpoint lookup returns tenant A's doc for a tenant-B user.

Root cause: two lookups fetch the newest `welcome-emails` doc with no tenant filter through the Payload local API (overrideAccess defaults to true, so `tenantBasedReadAccess` never runs):

1. `src/features/users/plugins/endpoints/index.tsx` (create user, email send)
2. `src/features/welcome-emails/plugins/queries/index.ts` `getLastWelcomeEmail` (Users page, modal prefill)

Also `welcomeEmailBody` falls back to `DEFAULT_RESPONSIBILITIES`; the ticket wants every editable section blank by default.

Decisions (developer): drop the default responsibilities list; flat `.plans` layout; repro against ct-dev.

## Files

- `src/features/welcome-emails/plugins/queries/index.ts`: add `getWelcomeEmailForTenant(payload, tenantId)` (filter `tenant equals`, `undefined` when no tenant id); `getLastWelcomeEmail(tenantId)` uses it.
- `src/features/users/plugins/endpoints/index.tsx`: resolve the new user's tenant id first, use the helper.
- `src/app/(dashboard)/dashboard/users/page.tsx`: pass `tenantContext.tenantIdForFilter`.
- `src/features/users/constants/welcomeEmailBody.ts`: remove default responsibilities; omit the Responsibilities block when empty.
- `src/features/users/components/welcome-email-modal/index.tsx`: update the empty-list hint.
- Tests: queries, email-bodies, endpoints, modal.

No migration, env var or dependency.
