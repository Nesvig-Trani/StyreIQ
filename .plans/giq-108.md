# GIQ-108 — Remove "Risk Description" from the Lost / Inaccessible Account form

Source of truth: [Linear GIQ-108](https://linear.app/meltstudio/issue/GIQ-108). Change request on GIQ-94 (client: Tristana, Oct 9, 2026).

Note: this plan was written after the first implementation pass, at the developer's request. The decisions below were not reviewed before coding, so they are open for review.

## Acceptance criteria

- [x] "Risk Description" removed from the Lost / Inaccessible Account form only; other flag types keep it.
- [x] Flag creation, listing and audit history work without the field (no required-field or null errors).
- [x] Existing Lost / Inaccessible flags that already have a description remain readable.

## Branching

Branched from the GIQ-109 test-suite branch so the change ships with tests. The PR should target that branch until GIQ-109 merges.

## Approach and decisions

1. **Form (`hooks/useCreateFlag.tsx`):** give the `description` field `dependsOn: { field: 'flagType', value: ENTITY_FLAG_TYPES }`, the same mechanism the entity fields use. It shows for Security Concern, Operational Issue and Other, and is hidden for Lost / Inaccessible Account.
2. **Schema (`schemas/index.ts`):** `description` becomes `z.string().optional()`. A hidden field must not block submit or send `undefined` into a required string.
3. **Details dialog (`components/flag-details`):** render the "Risk Description" block only when `flag.description` has a value. This keeps old lost-account descriptions readable and avoids an empty heading on new flags.
   - Trade-off: any flag with an empty description now hides the block, not only lost-account ones.
4. **Collection and endpoint: unchanged.** `description` in `plugins/collections` is already optional and `plugins/endpoints` passes `description` through, so there is no migration and no change to history, listing or queries.

## Out of scope

- Removing the DB column or `payload-types` change.
- The dropdown fix on the same form that the ticket mentions as bundleable (GIQ-105 covers the organizational unit field).

## Tests

- `create-flag-form.test.tsx`: field hidden for lost accounts, shown for entity flags; lost-account submit no longer fills the field.
- `flag-details.test.tsx`: no "Risk Description" block when there is no description; old description still shown for lost accounts.
