# GIQ-105 — Lost / Inaccessible Account form: Organizational Unit and Assigned To dropdowns are empty

Linear: [GIQ-105](https://linear.app/meltstudio/issue/GIQ-105)

## Context

On the Create Risk Flag form (Lost / Inaccessible Account), Tristana reported that "Organizational Unit" shows "No options available" and "Assigned To" is empty. Expected: units the admin can access, and after picking a unit, that unit's people as assignees.

Root cause found for Assigned To: `useCreateFlag` always used the page-level `users` list (all users the viewer can read in the tenant), never scoped to the chosen unit. The empty Organizational Unit dropdown could not be reproduced with a super admin, Central Admin or Unit Admin on the test tenant; `getAllUnits` swallowed errors silently.

## Changes

1. `useAssignableUsers(organizationId, roles = ASSIGNABLE_USER_ROLES)` — optional `roles` argument.
2. `src/features/flags/constants/assignableFlagUsers.ts` — `FLAG_ASSIGNABLE_USER_ROLES` (Central Admin + the social-media assignable roles).
3. `useCreateFlag` — for a lost account flag, after a unit is picked, Assigned To loads that unit's users and resets when the unit changes; clear empty-state messages for both dropdowns.
4. `select` field + `FieldData.emptyOptionsMessage` — configurable empty text.
5. `getAllUnits` — logs the error it used to swallow.
6. `createFlag` endpoint — server-side guard: for a lost account flag with a unit, the assignee must be a member of that unit with an assignable role and status (same rule as the form); otherwise 400 "The assigned user does not belong to the selected unit" and nothing is created.
7. Tests: endpoint guard (accepted query, rejection without writes), hook roles param, create-flag form (unit-scoped assignees, empty unit), select empty message, `getAllUnits` error logging.
